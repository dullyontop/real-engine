# RE8902: No answer from the server

A client sent its handshake for the whole timeout (10 s unless `[net]
timeout_ms` says otherwise) and no server finished it. Either nothing
answered, or answers came that failed the encrypted handshake: changed on the
way, or from something other than the server. The message says how many of
those came.

## Example

```text
error[RE8902]: no answer from a server at 192.168.1.20:47800 after 10 s
```

```text
error[RE8902]: no answer from a server at 192.168.1.20:47800 after 10 s; 3 answers came that failed the handshake (changed on the way, or from another server)
```

## How to fix it

Check that the server is running (`real run --server`), that the address and
port are the ones it printed when it started, and that no firewall between the
machines blocks UDP on that port. On the server machine, allow incoming UDP on
the port. Answers that failed the handshake mean that something on the way is
changing packets or answering for the server: try another network.
