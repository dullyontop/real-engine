# RE8910: WebSocket connection failed

Players in a browser reach a server over a WebSocket (ADR-0050, PR "web"),
and `real run --connect ws://HOST:PORT` does too. This one did not connect,
its handshake failed, or the connection broke while playing. The message says
which, with the address.

## Example

```text
error[RE8910]: cannot connect to ws://192.168.1.20:47800/: connection refused
```

## How to fix it

- Check that the server is running (`real run --server`) and that the address
  and port are the ones it printed. A server takes WebSocket players on TCP at
  the same port as UDP, unless `[net] websocket = false`.
- On the server machine, allow incoming TCP on the port.
- A page served over HTTPS may only open `wss://` addresses. The server speaks
  plain `ws://`, so put a TLS proxy in front of it (one that forwards
  WebSocket connections) and connect to the proxy's `wss://` address.
- A native build has no TLS: connect to `ws://` or, without a browser in the
  way, over UDP with `HOST:PORT`.

Online play is not encrypted, over UDP or WebSocket alike.
