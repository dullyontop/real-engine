# RE6032: Shader rejected by the GPU

naga accepted a shader given at run time, but the device refused the shader or
a pipeline built from it. This usually means the shader no longer matches what
the renderer feeds it: an entry point was renamed, a binding changed type, or a
vertex input or output moved.

The pipelines built from it keep their last good version. `real verify` cannot
catch this without a GPU; a run that draws reports it when the file is loaded.

## Example

```text
error[RE6032]: the GPU refused the pipelines built from `sky.wgsl`: In Device::create_render_pipeline, label = 're_render sky': Error matching ShaderStages(FRAGMENT) shader requirements against the pipeline: Unable to find entry point 'fs_sky'
  --> shaders/sky.wgsl
  = hint: keep the entry points, bindings and outputs of the engine's file when replacing it; the last good pipelines stay in use
```

## How to fix it

Keep the entry points, bindings and vertex interface of the engine's version of
the file; change the code inside them. The engine's files are in
`crates/re_render/src/shaders/`.
