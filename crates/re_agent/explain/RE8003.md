# RE8003: Project locked by another writer

A project has one writer at a time (ADR-0026). The editor, or else the first
headless writer (`real do`, `real mcp`), holds `.real/editor.lock`. Another
writer tried to take the lock while that process was still running.

## Example

```text
error[RE8003]: project is locked by 4242 (`real mcp`)
  --> .real/editor.lock
```

## How to fix it

- Stop the other process (the pid is in the message), then run the command
  again.
- Or start the editor (`real editor`). While it runs, `real do` and `real mcp`
  send their commands to it through `.real/editor.sock` instead of opening the
  project themselves, so they no longer conflict.

A lock left behind by a process that has exited is stale and is replaced
automatically. Readers (`real run`, `real verify`, `real describe`) never need
the lock.
