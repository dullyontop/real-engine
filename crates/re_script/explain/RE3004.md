# RE3004: Require refused or not found

`require` could not load a module.

In the `game` and `tools` contexts, `require` takes a path. Either the path did
not resolve to a `.luau`/`.lua` file (or a folder with an `init.luau`), it was
ambiguous, or it resolved outside the project's `scripts/` folder. Scripts may
only load modules from `scripts/`, so a project cannot read arbitrary files on
the machine.

In the `server` and `client` contexts of a compat project, `require` takes a
`ModuleScript` instance. It fails when the argument is not a `ModuleScript`,
when modules require each other in a cycle (the message lists the chain),
when the module raised an error while it loaded (every later `require` of it
fails too), or when the module did not return exactly one value.

## Example

```text
error[RE3004]: require of "secrets/keys.luau" is refused: modules must be inside scripts/
  --> scripts/game/main.luau:1
```

```text
error[RE3004]: Requested module was required recursively: ReplicatedStorage.A -> ReplicatedStorage.B -> ReplicatedStorage.A
  --> ReplicatedStorage.B:1
```

## How to fix it

Use a path relative to the requiring file (`require("./util")`,
`require("../shared/math")`), or an alias from the project's `.luaurc`
(`require("@shared/math")`), that points at a module inside `scripts/`.

In a compat project, pass the `ModuleScript` itself
(`require(game.ReplicatedStorage.Util)`). Break a cycle by moving what both
modules need into a third module, or by requiring one of them lazily inside a
function. Make each module end with one `return` of one value.
