# RE3103: Value a save cannot hold

`save.write` keeps a table of the game's data as JSON, and only data that
reads back exactly as written can go in it: tables of booleans, finite
numbers, strings and tables of them. An array is a table with the keys `1`
to `n` and nothing else; every other table has string keys only. A slot
holds at most 4 MiB as JSON, and its tables nest at most 64 levels deep.

The message names where the value is (`data.player.pos`) and what it is:

- a vector, an entity, a function or another engine value;
- `NaN` or an infinity;
- a number key that is not part of a sequence `1` to `n` (a gap, `0`, a
  fraction), or number keys mixed with other keys;
- a key that is not a string or a number;
- a string that is not UTF-8 text;
- tables nested deeper than 64 levels, or a table that holds itself;
- more than 4 MiB of JSON.

Nothing was saved; the slot keeps what it held.

## Example

```text
error[RE3103]: save.write: data.player.pos is a vector, which a save cannot hold; store {x, y, z} instead
```

## How to fix it

Store plain data and rebuild engine values when the game reads the slot:

```luau
local p = player:get("Transform").translation
save.write("slot-1", {
    scene = scene.current(),
    pos = { p.x, p.y, p.z },          -- not the vector
    target = target.id,               -- the entity's stable id, not the entity
})

local data = save.read("slot-1")
if data then
    local pos = vector.create(data.pos[1], data.pos[2], data.pos[3])
    local target = world.get(data.target)
end
```

A table with gaps (`{ [1] = a, [5] = b }`) can use string keys instead
(`{ ["1"] = a, ["5"] = b }`).
