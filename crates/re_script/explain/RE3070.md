# RE3070: The script reached a breakpoint where it cannot pause

A breakpoint (or the end of a step) was reached in code that cannot be
paused right now, so the debugger recorded the stack and the locals and let
the script continue.

A script can wait at a breakpoint in two ways. A script thread (an entry
script, a signal handler, `task.spawn`, `task.defer`, `task.delay`) is
parked, and the rest of the game keeps running. Code that cannot yield, such
as code inside `require`, a builder script, a metamethod or a `table.sort`
comparator, can only wait by holding up the whole VM until the debugger says
to go on. That only happens when a DAP client is attached to answer. In the
editor with no DAP client, holding up the VM would freeze the window, so the
script continues instead.

## Example

```text
warning[RE3070]: the script reached a breakpoint at scripts/shared/util.luau:12 where it cannot pause; its stack was recorded and it continued
  = help: attach a DAP client to stop here (the script then waits for it), or set the breakpoint in a script thread
```

## How to fix it

- The editor's debugger panel shows the recorded stack and locals under
  "Last stop (not paused)".
- To really stop there, attach a DAP client (port 4711 by default): the
  script then waits until you continue.
- Or move the breakpoint to the code in a script thread that calls this
  function.
