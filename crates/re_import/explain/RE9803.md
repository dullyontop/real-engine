# RE9803: Loader statement not recognised

The importer never runs a loader script. It reads it statically and
understands these shapes:

* `local x = <constant>` (strings, numbers, booleans, `nil`, tables of
  constants);
* `game:GetService("S")`, `game.S`, `workspace`;
* `Instance.new("C")`, and `x.Name =`, `x.Parent =`, `x.Source =`,
  `x:AddTag("t")`, `CollectionService:AddTag(x, "t")`, `x:Destroy()`;
* `do ... end` and `pcall(function() ... end)`;
* helper functions recognised by their bodies: one that creates an instance
  and sets its `Name` and `Parent`, one that resolves a path of names under a
  service (creating missing containers), and one that destroys the children
  with a given name;
* a table of script entries `{ {"Service", ..., "Name"}, "ModuleScript",
  source }`, applied the way such loaders apply them.

Any other statement is reported. At the top level of the file it is a
warning: the statement is skipped, not run, and listed under `unrecognised` in
the report. Inside a `do` block or a `pcall` body, where loaders build their
trees, it is an error and nothing is imported, because skipping it could build
the wrong tree.

## Example

```text
error[RE9803]: the loader builds instances with a statement the importer does not recognise: print("x")
  --> loader.luau:2650:1
```

## How to fix it

Remove the statement from the building block, or move it to the top level if
it only reports something. If the statement does build instances, write it in
one of the shapes above.
