# RE4092: No such override to revert

`proc.revert` puts back what a procedural source generates. With `id` it
removes the field overrides the source keeps for that generated entity (all
of them, one component's with `component`, or one field's with `field`) and
gives each field its generated value; with `source` and `key` it removes the
source's deletion override for `key` and brings the entity back. It was asked
to revert an override that is not there: the entity is not generated (an
authored entity keeps no overrides), the source keeps no field override of
what was named, `source` is not a procedural source, or the source keeps no
deletion override for `key`.

Nothing changes.

## Example

```text
error[RE4092]: `island` keeps no override of `Transform.scale` of `island/rocks/3`
  --> entity `island/rocks/3`
  = help: `entity.get {"id": "island"}` lists the overrides `island` keeps
```

## How to fix it

- Read the source with `entity.get {"id": "<source>"}`: its `overrides` list
  names each override by `target` (the key), `component` and `field`, or
  `deleted`.
- A generated entity's id is `<source>/<key>`: pass the key, not the id, as
  `key` for a deletion.
- An authored entity's fields are its own: set them with `entity.set`, or
  use `undo`.
