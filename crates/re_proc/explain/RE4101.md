# RE4101: Luau node over its budget

A Luau node ran more safepoints than its budget allows (by default
20,000,000 per evaluation, about 3 s; `[proc] luau_budget` in `real.toml`), or
used more memory than `[proc] luau_memory_mb` (256 MB by default). The budget
counts the VM's safepoints, so the same graph stops at the same place on every
machine; a `pcall` inside the node cannot catch it.

## Example

```text
error[RE4101]: node `rocks` (project.rocks): the Luau node ran past its budget of 20000000 safepoints
```

## How to fix it

Do less work per evaluation (smaller fields, fewer points), move bulk work
to a Rust node, or raise `[proc] luau_budget` for the project.

A `pcall` cannot catch the safepoint budget. It can catch running out of
memory (the call returns `false, "not enough memory"`), so a script that
does so makes its output depend on `luau_memory_mb`; let memory errors
propagate.
