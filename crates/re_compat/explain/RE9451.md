# RE9451: Owned change stays on the client

A `LocalScript` changed a component of an instance its player owns (its
character, or a part the server gave it with `SetNetworkOwner`), but that
component does not flow from clients to the server in a networked game. The
change stays on this client; the server and the other players do not see it.
It is reported once per component.

By default an owner may change only motion: a part's position, orientation
and velocities, the `Humanoid`'s movement state and the `Animator`'s playing
tracks (ADR-0050 §2).

## Example

```text
warning[RE9451]: a client change to Highlight on an owned instance stays on this client: networked games send only [compat.net] upstream components to the server
```

## How to fix it

Make the change on the server: fire a `RemoteEvent` and let a server
`Script` change the instance. To let clients send more components, list
them in `real.toml`:

```toml
[compat.net]
upstream = ["Transform", "Velocity", "Humanoid", "Highlight"]
```
