# RE9455: Networked run differs from the in-process run

`real verify`'s `net` stage plays each replay twice: in one process, and
as a dedicated server and one client over loopback, both with `--lockstep`
(ADR-0050 §7). In lockstep the server sees exactly what the in-process
server sees, so the two server worlds must end with the same state hash.
This one did not, or the server or the client could not run.

## Example

```text
error[RE9455]: tests/replays/walk.replay.json: the networked server ended with state hash 1f3a… and the in-process run with 71cb…
```

## How to fix it

Rerun the pair by hand to see both sides' diagnostics:

```sh
real run --server --lockstep --bind 127.0.0.1 --port 47900 --frames 900 --json
real run --connect 127.0.0.1:47900 --lockstep --headless --replay tests/replays/walk.replay.json
```

A difference usually means a client changes something that reaches the
server in one process but not over the network: a component outside
`[compat.net] upstream` (the client reports it as `RE9451`), or an
owned part moved faster than `max_owned_speed` (`RE9452`). Widen
`upstream`, or make the change on the server. If neither applies, it is
an engine bug: report it with the replay.
