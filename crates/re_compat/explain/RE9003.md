# RE9003: Invalid compat data file

A class, enum or library data file of the compatibility layer
(`crates/re_compat/classes/*.json`, `enums/*.json`, `libraries/*.json`) is
malformed or inconsistent. The class registry refuses to build, so the error
shows up in the crate's tests and in `cargo xtask coverage`.

Typical causes:

* a wrong `format` or `version`, or a field the format does not have;
* a class declared twice, or an `extend` entry for a class nobody declares;
* a member declared twice on one class, or a member that reuses an inherited
  member's name with a different kind (a method named like a property);
* an unknown superclass, a cycle of superclasses, or a class other than
  `Instance` with no superclass;
* a `partial` row with no `note` saying what is missing;
* an `own` property whose type has no field type (an unknown `Enum.<Name>` or a
  record type that is not registered), or whose `default` does not fit it;
* a `via` converter, or an accessor for an `implemented` builtin property, that
  was not registered.

## Example

```text
error[RE9003]: invalid compat data: classes/parts.json: Part.Anchored is partial but has no note saying what is missing
```

## How to fix it

Correct the file the message names; the JSON Schemas in `schemas/compat-*.schema.json`
describe every format. Then run `cargo xtask coverage` to regenerate `coverage.json`.
