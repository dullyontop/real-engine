# RE2056: Transaction breaks the rule of what is being edited

While some worlds are edited, the World must keep a rule after every
transaction. While a prefab is open in the editor (`scene.open` of a
`*.prefab.json`), it must keep exactly one root entity, and no entity may have a
`Procedural` component, because a prefab is placed as one subtree and procedural
sources are not allowed inside prefabs. A transaction, undo, redo or dry run that
would leave the World breaking the rule is rolled back, and nothing changes.

## Example

```text
error[RE2056]: a prefab has exactly one root entity; this edit leaves 2 (`crate`, `lamp`)
```

## How to fix it

Keep the prefab's entities under its root: parent a new entity to the root, or
reparent it there in the same transaction. Bake procedural content into authored
entities (`proc.bake`) in a scene before making a prefab of it.
