# RE8853: An asset's thumbnail could not be made

The Assets panel shows a thumbnail of each texture and material in its grid:
a texture's pixels, shrunk to 96 pixels on its longest side, and a material
drawn on a sphere in a fixed light. The editor makes them on its asset index
thread, without loading anything into the game, and keeps them on disk under
`.real/cache/thumbs/`, keyed by the bytes of the file (and of the textures a
material names), so each is made once.

This warning says that one could not be made. The panel shows the asset's
kind instead, and does not try again until the file changes. Nothing in the
project was changed, and the game loads the asset as it would without the
editor: a texture that cannot be decoded here fails there too.

## Example

```text
warning[RE8853]: no thumbnail for assets/textures/bark.png: cannot decode assets/textures/bark.png: Format error decoding Png: Invalid PNG signature.
  --> assets/textures/bark.png
  = help: the Assets panel shows its kind's icon; the thumbnail is made again when the file changes
```

## How to fix it

- A texture must be a PNG or a JPEG (the game's loader refuses others with
  `RE7003`). Save it again from your image editor, or replace it; the panel
  makes its thumbnail when the file changes.
- A material must be a valid `*.material.json` file whose textures exist:
  open it in the Material panel to see what is wrong (the game's loader
  reports it as `RE7010`, `RE7011` or `RE7012`), and fix the file or the
  texture path.
- If a thumbnail looks wrong rather than missing, delete
  `.real/cache/thumbs/`: it is only a cache, and the editor makes the
  thumbnails again.
