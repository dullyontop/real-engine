# RE4515: Modelling result too large

A modelling operation's result would have more than 16,777,216 (2^24) points
or corners. The limit bounds the memory one node's output can take at a few
hundred megabytes. The operation computes its result's size first, so it
refuses before allocating anything.

Subdivision is the usual cause: each level of `poly.subdivide` multiplies the
number of corners by about four, so four levels multiply it by about 256.

## Example

```text
error[RE4515]: the result would have 6291458 points and 25165824 corners, more than the 16777216 allowed
```

## How to fix it

Use fewer subdivision levels, segments or copies, or model the object in
pieces: several smaller meshes, each its own node output, draw as several
entities.
