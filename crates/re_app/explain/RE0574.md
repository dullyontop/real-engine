# RE0574: Bad save or settings file

A file where a save slot belongs is not a save: it does not parse as JSON,
its `format` is not `real-engine/save`, it was written by a newer engine
(a higher file `version`), or a field is missing or wrong.

- In the data folder, the file is set aside as `<slot>.json.bad` (or
  `.bad.1`, `.bad.2`, ... when an older one is there), so it is kept and never
  overwritten, and the slot reads as empty.
- In the project's seed (`data/seed/saves/`, where verify runs, replays and
  every run that keeps no data start), the file is skipped and the slot starts
  empty. `real verify` fails on it.

This is a warning: the game goes on.

## Example

```text
warning[RE0574]: data/seed/saves/slot-1.json is not JSON (EOF while parsing an object at line 3 column 0); the slot starts empty
  --> data/seed/saves/slot-1.json
```

## How to fix it

A save file looks like this (`saved_at` is seconds since 1970, UTC, and
`data` the table the game saved):

```json
{
  "format": "real-engine/save",
  "version": 1,
  "data_version": 1,
  "saved_at": 1767225600,
  "data": { "coins": 12, "visited": ["town"] }
}
```

Fix the file, or write the slot again from the game. A file set aside from
the data folder can be repaired and renamed back to `<slot>.json`.
