# RE0501: Invalid real.toml

`real.toml` could not be read, has a TOML syntax error, an unknown key, a value
of the wrong type or a value out of range (for example `[sim] fixed_hz = 0`,
or `[render.shadows] cascades = 6`). Values are reported as written; nothing is
clamped.
The same code is used when the `[input]` bindings name keys or buttons that do
not exist; the input diagnostics are attached as related notes.

## Example

```text
error[RE0501]: invalid real.toml: unknown field `bogus`, expected one of `fixed_hz`, `max_steps_per_frame`, `gravity`
  --> real.toml:5:1
```

## How to fix it

Fix the key or value at the reported line. The sections and their keys are
`[project]`, `[sim]`, `[render]`, `[scripts]`, `[input]` and `[verify]`
(ARCHITECTURE §8). `real new` writes a complete example.

`[render.post]` and `[render.shadows]` hold a native project's post-processing
and sun shadows (ADR-0038); their keys are the fields of `PostSettings` and
`SunShadows`, and every key may be left out. The ranges are:

| Key | Range |
|---|---|
| `[render.post] exposure`, `blur_radius` | 0 or more |
| `[render.post] tone_mapping` | `"None"`, `"PbrNeutral"`, `"Aces"` or `"AgX"` |
| `[render.post.bloom] intensity`, `threshold`, `radius` | 0 or more |
| `[render.post.bloom] knee`, `[render.post.sun_rays] spread` | 0 to 1 |
| `[render.post.sun_rays] intensity` | 0 or more |
| `[render.post.grading] contrast`, `saturation` | -1 or more |
| `[render.post.grading] tint` | three values, each 0 or more |
| `[render.shadows] cascades` | 1 to 4 |
| `[render.shadows] distance` | more than 0 |
| `[render.shadows] split_lambda` | 0 to 1 |
| `[render.shadows] blend` | 0 to 0.5 |

```toml
[render.post]
exposure = 1.0
tone_mapping = "PbrNeutral"

[render.post.bloom]
intensity = 0.2
threshold = 1.0

[render.shadows]
cascades = 4
distance = 150.0
```
