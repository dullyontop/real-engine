# RE0578: A kept entity stands in for a scene's entity

A scene was loaded while an entity with the same id was kept across switches
(`scene.keep`). The scene's entity, with its subtree, was not spawned: the
kept one stands in for it, and the scene's references to that id point to
the kept entity. This is a note, not an error: it lets every level hold its
own player for testing on its own, while the player carried from the last
level wins.

## Example

```text
note[RE0578]: the kept entity "player" stands in for the entity of that id in the scene "town"
```

## How to fix it

Nothing to fix when this is what you meant. To load the scene's own entity,
stop keeping the old one (`scene.keep(e, false)`) before the switch.
